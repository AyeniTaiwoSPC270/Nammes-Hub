One thing to decide

The support links are a network dependency

SocialIcons filters its links against useSiteContentQuery(), which needs the network we just lost — so on a real offline render it would come back empty, exactly when the user most wants a way out. The mockup shows them populated. I’d add a small static fallback in SocialIcons (or render the icons locally on this screen) rather than ship a screen whose only escape hatch disappears offline. Tell me which you prefer.
