# NAMMES Hub — Design System

Working identity. Forest green + orange, single sans-serif family (Public Sans) across display, body, and label text, flat design with a mix of borderless colored-fill surfaces (brand-tone cards) and bordered white surfaces (neutral cards, tables, inputs). Pills are used for badges/toasts; buttons and cards are rounded rectangles, not pills. Two themes — light and dark — with a manual switch in the navbar and on the quiz screens; see Dark mode below.

Tokens live in `src/index.css` as CSS custom properties inside `@theme` (Tailwind v4), so every value below is available as a utility class (`bg-green-900`, `text-ink-muted`, `font-display`, `rounded-lg`, …). **This file is generated by reading the actual tokens in `src/index.css` and the real component implementations in `src/components/` — treat those as the source of truth, not any external handoff folder, since they've drifted from earlier handoffs over time.**

## Dark mode

Dark mode is implemented and shipped. This section replaces an earlier claim in this file that there was no dark theme and no toggle; that was wrong.

- **Variant** — `@custom-variant dark (&:where(.dark, .dark *))` at `src/index.css:3`, so any utility takes a `dark:` prefix against a `.dark` ancestor. Write `bg-surface dark:bg-surface-low`, not a JS branch on the theme.
- **Scheme** — `:root { color-scheme: light }` (`src/index.css:47-49`) and `.dark { color-scheme: dark }` (`:51`), which is what makes form controls, scrollbars and the canvas follow the theme without extra rules.
- **Overrides** — the `.dark` block at `src/index.css:51-64` redefines only the tokens that must change:

  | Token | Light | Dark |
  |---|---|---|
  | `ink-900` | `#000904` | `#f7f9f7` |
  | `paper` | `#fcf9f8` | `#0d1310` |
  | `surface` | `#ffffff` | `#16211b` |
  | `surface-low` | `#f6f3f2` | `#111a15` |
  | `ink` | `#1c1b1b` | `#e6e8e5` |
  | `ink-muted` | `#424843` | `#9aa79e` |
  | `hairline` | `#c2c8c1` | `#2c352f` |
  | `brand` | `#0b2417` | `#5cb88a` |
  | `brand-orange` | `#ae3200` | `#ff9a5c` |

  `green-900`, `orange-*`, `success*`, `warning*` and `danger*` are deliberately **not** overridden — those are brand fills and status colours that stay the same in both themes, which is why `bg-green-900` stays a dark band with white text in either mode.
- **Owner** — `src/lib/ThemeContext.jsx`. `localStorage` under `nammes-theme`, falling back to `prefers-color-scheme`, and it keeps following the OS while the reader has made no explicit choice. `useTheme()` returns `{ theme, toggleTheme }` and throws outside a `ThemeProvider`.
- **Before paint** — `public/theme-init.js` is a blocking script in `index.html` that adds the `dark` class from `localStorage`/`prefers-color-scheme` before first paint. Without it the page renders light and snaps dark, so don't remove it or move it into the bundle.
- **Exposed** — `Navbar.jsx` (`ThemeToggle`, desktop and mobile) and `src/components/quiz/QuizThemeToggle.jsx` for the quiz screens, which have no site header.

## Calendar

The `/calendar` page is the only page with a per-page re-skin. Its theme is `jsonb` on `calendar_looks`, designed in the Calendar Design Studio, and cleaned by `sanitizeTheme` (`api/_lib/calendarTheme.js`) — the only judge, on the way into the studio, into the preview, into the row and out to the page.

**Swatches.** A theme stores a *swatch id*, not a CSS value, so an accent re-skins through the token it names and follows the site into dark mode for free. The list is closed (8, `SWATCHES` in `calendarTheme.js`), each mapped to a real `@theme` colour:

| Swatch | Label | Token |
|---|---|---|
| `brand` | Brand | `--color-brand` |
| `forest` | Forest | `--color-green-900` |
| `flame` | Flame | `--color-orange-500` |
| `ember` | Ember | `--color-orange-600` |
| `sand` | Sand | `--color-orange-100` |
| `success` | Green | `--color-success` |
| `warning` | Amber | `--color-warning` |
| `danger` | Red | `--color-danger` |

An admin who wants a colour off the list types a hex into the **Advanced** disclosure. The hex is kept alongside the swatch id, never instead of it, so the picker still shows something chosen and one click returns to a curated colour. An off-list or malformed hex falls back to the kind's seeded swatch.

**Per-kind defaults** — one colour, icon and label each, for the seven `academic_calendar.kind` values: lectures `brand`/`school`, exams `danger`/`assignment`, registration `warning`/`edit_note`, break `sand`/`beach_access`, convocation `ember`/`workspace_premium`, orientation `flame`/`groups`, other `forest`/`event`. Icons are held to a closed picker list (`CalendarDesignControls.jsx`) because an icon the font wasn't asked to load renders as its own name in text; `CalendarDesignControls.test.js` holds the list against `icon_names=` in `index.html`.

**`--cal-*` custom properties.** `themeVars` (`calendarTheme.js:191`) emits these onto the calendar wrapper (`Calendar.jsx:185`), alongside the app-level tokens `src/lib/formTheme.js:419` already knows how to apply — the same CSS-variable re-skin approach, applied at page scope instead of a single form:

| Property | Values | What it drives |
|---|---|---|
| `--cal-accent` | a swatch token, or the admin's hex | The page accent, read indirectly: `themeVars` repoints `--color-brand` and `--color-green-900` at it, so the active view pill (`bg-green-900`) and the `text-brand` links inside the calendar follow it. `brand-orange` is not repointed |
| `--cal-radius` | `4px` / `8px` / `12px` / `9999px` (sm/md/lg/full) | Mirrors `--radius-*` so a calendar card and a site card would round the same corners. **Emitted but not yet read** — no component consumes it, so the studio's radius control currently changes nothing on the page; the grid still uses the Tailwind radius utilities |
| `--cal-cell-min` | `112px` comfortable, `84px` compact | Minimum grid cell height (`MonthGrid.jsx:307`) |
| `--cal-row-pad` | `10px` comfortable, `4px` compact | Vertical padding inside a grid cell (`MonthGrid.jsx:283`) |
| `--cal-<kind>` | one per `KIND_ORDER` value | The item's accent: dot, bar left-border and legend swatch in `MonthGrid`, `AgendaList`, `DaySheet`, `NextUpStrip`, `TbaPanel`, `CalendarLegend` |

`themeVars` only emits `--color-brand` and `--color-green-900` when that actually changes something. Pointing a token at a swatch that *is* that token is a custom-property cycle, and CSS drops the whole chain to its initial value — light mode would fall back silently and dark mode not at all.

The grid and legend read `var(--cal-<kind>)`, never a hex, which is what keeps the calendar legible in both themes off one swatch list. **Unverified without a real session:** how each of the eight swatches actually reads against the grid, the bars and the day sheet in dark mode.

Visual rules: backgrounds are flat, no gradients/patterns except the Hero's photo-with-overlay treatment (see Pages below). Cards are a mix: `tone="neutral"` cards are bordered white surfaces (`border border-hairline shadow-md`); `tone="green"`/`tone="orange"` cards are borderless solid-fill surfaces. Shadow (`shadow-sm`/`shadow-md`) is used more broadly than "floating elements only" — neutral cards, the sticky mobile nav panel, and skeleton cards all carry `shadow-md` at rest.

## Typography

There is currently **one font family** (`Public Sans`) mapped to all three type roles — `font-display`, `font-body`, and `font-mono` all resolve to `"Public Sans", -apple-system, sans-serif` in `src/index.css`. There is no serif display face and no monospace face loaded despite the token names; if a future handoff reintroduces a serif/mono pairing, update the `--font-*` values in `@theme` and this doc together.

- **Display** (`font-display`) — applied automatically to `h1`–`h3` via the base layer rule (`font-display font-semibold text-ink-900`, `leading-tight` 1.15).
- **Body / UI** (`font-body`) — default body text, buttons, form controls.
- **"Mono" / labels** (`font-mono`) — eyebrows, uppercase kickers, badge text. Visually identical to body text (same font), distinguished only by size/case/tracking, not by typeface.

Type scale: Tailwind defaults (`text-xs` through `text-5xl`), no invented sizes. Common patterns in the codebase:

| Role | Class |
|---|---|
| Eyebrow / kicker | `text-xs uppercase tracking-[.05em] font-bold` (Card) or `font-semibold` (FormField label, orange-600) |
| H1 (Hero) | `text-3xl sm:text-5xl font-bold` |
| H2 (section) | `text-2xl sm:text-3xl font-bold` |
| H3 (card title) | `text-xl font-bold` |
| Body | `text-base leading-relaxed` |
| Small / meta | `text-sm text-ink-muted` |

## Spacing & shape

Tailwind's default spacing scale (4px increments, including fractional multiples like `py-3.5`/`px-4.5`). Section rhythm: `py-16` between major Home sections, `gap-5`/`gap-6` within a grid.

Radius tokens overridden in `@theme` — **these are meaningfully smaller than a typical "pill" system**:
- `rounded-sm` → 4px (form inputs' base, skeleton bars)
- `rounded-md` → 8px (buttons, Navbar dropdown panel, mobile nav panel, "Sign In" link)
- `rounded-lg` → 12px (cards, EmptyState/ErrorState, AuthCard shell)
- `rounded-full` → pill (badges, toasts, avatar circles) — **not** used for buttons

Shadow: `--shadow-sm: 0 1px 3px rgba(0,0,0,.06), 0 1px 2px rgba(0,0,0,.04)`, `--shadow-md: 0px 4px 20px rgba(0,0,0,.05)`. Motion: `duration-150` for hover/transition; `Button` also does a subtle `hover:scale-[1.03]` / `active:scale-[0.98]`.

## Components

All in `src/components/ui/` (`Button`, `Card`, `Badge`, `Table`, `FormField`, `EmptyState`, `ErrorState`, `Skeleton`, `Toast`) plus `src/components/{Navbar,Footer,AuthCard}.jsx`.

### Button

Props: `variant` (`primary`|`secondary`|`accent`|`destructive`|`ghost`), `size` (`md`|`sm`), `loading`, `disabled`, `onClick`, `type`, `className`.
- **Rounded rectangle** (`rounded-md`, 8px), 1px border matching fill color (via Tailwind's `border` default width, not a heavier 2px), `font-body font-bold`, sentence case labels, no icons.
- primary: `bg-green-900 border-green-900 text-white`, hover → `opacity-90`. secondary: `bg-surface-low border-transparent text-green-900`, hover → `bg-hairline/40`. accent: `bg-orange-500 border-orange-500 text-white`, hover → `bg-orange-600`. destructive: `bg-danger border-danger text-white`, hover → `#93000a`. ghost: `bg-transparent border-transparent text-ink`, hover → `bg-surface-low`.
- Hover/active: `hover:scale-[1.03]` / `active:scale-[0.98]`, 150ms ease (skipped when disabled/loading).
- Disabled/loading: `opacity-50 cursor-not-allowed`, loading replaces children with "Loading…".
- md: `28px/14px` padding (`px-7 py-3.5`), base text. sm: `18px/8px` padding (`px-4.5 py-2`), sm text.

### Card

Props: `eyebrow`, `title`, `meta`, `children`, `padded` (default true), `tone` (`neutral`|`green`|`orange`), `image` (`{ src }`), `imageVariant` (`icon` default | `cover`), `imageAspect` (`standard` | `video`), `backgroundImage`, `layout` (`column` default | `row`), `interactive`, `clampBody` (default true).
- `rounded-lg` (12px), `overflow-hidden`. **Only `tone="neutral"` gets a border** (`border border-hairline shadow-md`) — `green`/`orange` tones are borderless solid fills, matching the "colored-fill surface" identity.
- neutral: white bg, orange-600 eyebrow, ink-900 title, ink-muted meta, ink body. green: green-900 fill, orange-500 eyebrow, white title, white/70 meta, white/90 body. orange: orange-100 fill, orange-600 eyebrow, ink-900 title/body.
- `layout="row"`: flex row on `md:` and up (image left, content right on desktop, stacked on mobile) — used for the Home "featured" news card.
- `interactive`: adds `hover:-translate-y-0.5 hover:shadow-md`.
- `image` + `imageVariant="icon"` (default): 64×64 (`h-16 w-16 object-contain`), rendered inside the padded content above the eyebrow. Always decorative (`alt=""`, `aria-hidden`).
- `image` + `imageVariant="cover"`: full-bleed, `object-contain` inside a `bg-surface-low` frame (not `object-cover`/cropped as an earlier spec assumed), fixed aspect via `imageAspect` (`standard`=4:3, `video`=16:9). Used for real uploaded photos (News, Events) — not decorative illustrations.
- `backgroundImage`: an alternate full-bleed background-image mode with a tone-colored 80%-opacity scrim over it (used by the Home hero pattern, not currently wired through `Card` itself in `Home.jsx` — the Hero section there is hand-built rather than using `Card`).

### Badge

Props: `tone` (`new`|`updated`|`restricted`|`neutral`), `children`. Word only, no icons/emoji.
- `rounded-full` pill, `10px/2px` padding (`px-2.5 py-0.5`), `font-mono text-xs uppercase tracking-[.03em] font-medium`.
- new: `bg-orange-100 text-orange-600`. updated: `bg-success-bg text-success`. restricted: `bg-danger-bg text-danger`. neutral: `bg-surface-low text-ink-muted`.

### Table

Props: `columns` (string[]), `rows` (string[][]). Always wrapped in `.nm-table-wrap` (`overflow-x-auto`).
- `rounded-sm` (4px, not `rounded-md`), 1px hairline border, `border-collapse`.
- Header row: `surface-low` bg, `text-xs font-semibold uppercase tracking-[.05em] text-ink` (not mono — same font as body).
- Body cells: `px-4 py-3 text-sm text-ink`, hairline bottom border between rows (last row borderless), row hover → `bg-surface-low`.

### FormField

Props: `label`, `type` (`text`|`email`|`password`|`select`|`textarea`|…), `value`, `onChange`, `placeholder`, `helper`, `error`, `success`, `options`, `required`.
- Label: `text-xs font-semibold uppercase tracking-[.05em] text-orange-600` (not green-900 — labels use the accent color, not the brand green).
- Control: `rounded-md` (8px, not `rounded-sm`), `px-3 py-2.5 text-base`, border color state-driven: `border-danger` on error, `border-success` on success, `border-hairline` otherwise; focus → `border-green-900`.
- Helper/error/success text below the control — error takes priority, then success ("Looks good"), then helper.

### EmptyState / ErrorState

- `EmptyState`: `rounded-lg border border-hairline bg-surface-low` card, centered icon badge (`material-symbols-outlined` in a white circle), bold title, optional muted description. Used across list pages (News, Events, Excos) for the zero-data case.
- `ErrorState`: `rounded-lg bg-danger-bg` block, danger-colored heading, message, optional "Try again" destructive-variant `Button` wired to a `onRetry` refetch.

### Skeleton (`SkeletonText`, `SkeletonCard`, `SkeletonTable`)

Loading placeholders built from `animate-pulse bg-hairline` bars, matching the shape of the real content (`SkeletonCard` mirrors `Card`'s `rounded-lg border shadow-md` shell; `SkeletonTable` mirrors `Table`'s wrapper).

### Toast

Props: `tone` (`success`|`danger`), `onDismiss`, `children`. `rounded-full` pill (unlike buttons — toasts are one of the few actual pill shapes), solid tone fill, dismiss `✕` button.

### AuthCard

Props: `children`, `footer`, `below`, `maxWidth`. Centered shell for all four auth pages (Login/Signup/ForgotPassword/ResetPassword): `bg-surface-low` full-height wrapper, `rounded-lg border border-hairline shadow-md` card, optional bordered footer strip, optional text below the card (e.g. "Already have an account?").

### Navbar

Sticky, `z-30`, **solid** `bg-surface` with a 1px `border-hairline` bottom border — no translucency or backdrop-blur despite an earlier spec calling for one.
- Brand: 32×32 `/logo.png` + `font-display text-xl font-bold text-ink-900` wordmark "NAMMES Hub".
- Desktop (`sm:` and up) nav items: `About`, `Academics` (dropdown: Outlines/Timetable/CGPA/Resources), `Community` (dropdown: Events/News/Opportunities/Awards), `Forms`, `Contact`. Each link is `rounded-sm px-3 py-2 text-sm font-semibold`; **active state is a bold text + `border-b-2 border-ink-900` underline**, not a filled pill background. Inactive: `text-ink-muted`, hover → `text-ink-900 bg-surface-low`.
- Dropdown trigger (`NavDropdown`): same link styling plus a `material-symbols-outlined` chevron (`expand_more`/`expand_less` text glyph, not an SVG icon set). Open panel: `absolute … rounded-md border border-hairline bg-surface shadow-md`, active child gets `bg-green-100 text-green-900` (Tailwind default green-100/700, not custom tokens).

## Accessibility checklist (project-specific)

- `:focus-visible` ring is global (orange-500, 2px, 2px offset) — don't override it per-component.
- Admin delete actions need a confirmation step (native `confirm()` is acceptable for v1) — never a one-click destructive action.
- Course/event/resource lists will eventually be data-driven and potentially long — plan for pagination once real content exceeds ~50 rows.
- Re-verify contrast manually whenever a color token changes — the current `ink-900`-on-`paper` and `green-900`-on-`surface` pairs both clear 4.5:1.
