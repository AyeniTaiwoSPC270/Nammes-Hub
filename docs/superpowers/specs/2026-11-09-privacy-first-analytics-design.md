# Privacy-First Product Analytics and Experimentation

`page_views` records traffic but nothing answers "do students finish quizzes?" or "does the new outlines
layout help?" — product decisions run on vibes; and raw page_views grows unbounded with PII-adjacent paths.

**Status:** draft. **Date:** 2026-11-09. **Plan:** none yet.

---

## 1. Scope

### In

| Piece | What it is |
|---|---|
| Events | Named funnel events: `hub_view`, `outlines_open`, `cgpa_calculate`, `quiz_join`, `quiz_complete`, `cbt_submit`, `award_vote` |
| Storage | New `funnel_events(at, event, props jsonb)` table written ONLY via a security-definer RPC `record_funnel_event()` — the exact same one-writer pattern as `record_page_view()` (revoke from anon/authenticated, RPC validated server-side). No client inserts into analytics tables, ever |
| North Star | "Weekly engaged students" = distinct users with ≥3 meaningful events / WAU |
| Experimentation | A/B via `feature_flags.variant`; deterministic assignment hash(user_id) |
| Dashboard | Admin analytics gains the funnel + North Star cards (pairs with rollup spec) |
| PII rules | No raw queries with emails/names; `user_id` only; IP never stored |

### Out

- **PostHog/Segment.** External SaaS adds cost + privacy surface; keep in-house, revisit at 10k MAU.
- **Session recording.** Never on this user base.

---

## 2. The problem

The hub is funded effort, not money — its survival metric is *demonstrated value* (students using outlines/CGPA/quizzes), which is currently unmeasured. Without a funnel, exec decisions (which features to build for the next semester) are arguments, not evidence.

## 3. Decisions

| Decision | Choice | Why |
|---|---|---|
| Events | Flat, past-tense names; props ≤ 6 keys | Grep-able, cheap |
| Assignment | `hash(user_id + flag_key) % 100` buckets | Deterministic, no storage needed |
| Analysis window | Last full week + same-week-last-semester | Semesterality is real in academics |
| Reporting | Weekly 5-line readout in ADMIN.md log (auto-generated by rollup job) | Read, not just gathered |
| Retention | 13 months (pairs with migration-hygiene spec) | Enough for YoY comparison |

## 4. The change

Migration: Migration: create `funnel_events` + `record_funnel_event(p_event, p_props)` (validates event name against an allowlist, strips any email-like strings from props, no IP/user — viewer uuid semantics copied from `page_views`). `src/lib/track.js` calls `supabase.rpc('record_funnel_event', …)` — **a DB RPC, not a serverless function, so it consumes none of the 12 Hobby-plan slots**. Funnel cards in `pages/admin/AdminAnalytics.jsx` read via the existing `admin_analytics()` RPC pattern (re-declared with the new aggregates, per the house convention of wholesale re-declaration). Variant assignment in `flags.js`. Weekly digest appended by the analytics-rollup worker.

## 5. Verification

1. Events arrive with correct names/props in staging; funnel computes end-to-end on seed data.
2. A/B: two cohorts see different outline list density; conversion delta renders in dashboard.
3. PII sweep: `props` contains no email-like strings on sampled rows (regex check in rollup).

## 6. Risk

Event sprawl — every event needs an "owner + question it answers" one-liner in code; unused events are pruned quarterly. Experimentation on a small campus cohort can be underpowered; treat early results as directional, never p-hack.
